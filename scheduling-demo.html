粘性 · 席位 · TTL · 并发：一家连锁餐厅

店 = VM（一个账号）　桌 = 席位　灶 = 并发　登记本 = 粘性　半成品 = prompt 缓存。为了看得清，图里每店按 6 席位 / 2 并发 缩小演示；你的实际配置是 20 席位 / 2 并发 / 粘性 24h / 粘性等待 45s / 流空闲 180s。
--:--

图例

圆形人像一个会话（一个 Claude Code 窗口 / 子 agent）
彩色方块一次请求（一道菜），在灶上 = 正在向上游执行
桌子席位：请求进行中占用，结束立即释放
灶并发：同一账号同时在跑的请求数
登记本粘性：会话 → 店的记忆，不占桌子，每次成功续期
半成品prompt 缓存：留在那家店的后厨，过 TTL 就扔

对应配置

席位上限inference.session_slots（默认 20，硬上限 20）
并发concurrency.default_max_per_account / 分档 / 单槽覆盖
粘性 TTLsticky.ttl_seconds = 86400，滑动续期
粘性等待failover.sticky_wait_timeout_ms = 45000
流空闲时间failover.stream_idle_timeout_ms = 180000
缓存 TTL上游 prompt cache：默认 5 分钟，ttl:"1h" 为 1 小时
