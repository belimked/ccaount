01通用约定

请求

  • 所有调用都是 POST，地址 https://api.rexsoftware.com/v1/rex/{Service}/{method}，请求体是 JSON，键名就是方法的参数名。
  • 地址有三种等价写法：/Contacts/findMatchingContacts、/Contacts::findMatchingContacts、/contacts/find-matching-contacts。本清单统一用第一种。
  • 测试账户和正式账户是同一个地址。
Authorization: Bearer <token>
Content-Type: application/json
X-App-Identifier: Integration:PlaceSunnybank:Portal
X-Api-Option: use_status_codes=true,use_strict_arguments=true

X-App-Identifier 每个请求都要带，值是 Rex 邮件里给的例子，正式名称待定。申请 Verified Integrator 也以此为前提。

返回

  • 统一外层：{"result": …, "error": null}。error 不为 null 即失败；下文“期望返回”写的都是 result 的内容。
  • token 失效返回 TokenException：重新登录后重试一次。
  • search 类接口返回 {rows, total}；system_ 开头的字段只读。
  • update 支持只发改动的部分。related 里的行：带 id 是修改，不带 id 是新增，加 destroy 是删除，没发的行不动。

限制

  • 每个中介账户每小时 3,600 次请求。现在是软限制，Rex 说以后会严格执行。
  • token 默认 1 小时活动期，登录时用 token_lifetime 可设到 1 周。
  • 不发 is_dnd：它会把四个渠道开关一起重置。
  • API 写入和手工录入一样会触发 Rex 自动化。
读 不改变 Rex 数据写 新建或修改 Rex 数据会话 登录和身份Rex 邮件确认文档已核对待测试账号验证候选 / 待定
