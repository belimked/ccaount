原型任务清单与待确认事项（Web 交互原型）

原型阶段（P）· 8 个工作日 · 共 17 项任务、126 小时 · 20 项待确认。形式：Web 交互原型（iOS / 安卓界面也在 Web 上演示）。工时与 开发评估 第 8 节一致。

1. 原型目标与范围

  • 原型全部放在 Web 上：一个演示网址，包含 Web 管理署后台，以及按 iOS、安卓样式设计的手机界面（显示在手机外框中，可切换两种样式）。
  • 手机界面内含两种角色：司机（扫码抽油作业）和管理署（查看、更新餐厅，审核司机）。
  • 可以简单交互：页面跳转、填写表单、筛选列表、开始 / 结束作业，数据保存在浏览器本地，可一键重置。
  • 没有原生功能：扫码、定位、拍照都用模拟操作代替（例如“模拟扫码”从餐厅列表中选择）；不需要后端和数据库，也不出 iOS / 安卓安装包。
  • 原型不含：真实扫码 / 定位 / 拍照、离线模式、车辆与挂车、卸货、警告与罚款、报表、多租户。

5. 需要和客户确认的事项

⬇ 下载 Excel 版（用于记录客户答复）

建议在启动前的确认会（D0）上逐条过一遍。客户暂时无法答复的，原型先按“建议默认方案”实施，演示时再确认。标“重要”的会影响数据结构，请优先确认。

编号问题建议默认方案影响客户答复
业务流程
Q01“进行中的作业”按司机判断还是按餐厅判断？例如司机在 A 餐厅的作业未结束，又扫了 B 餐厅。按司机判断：一个司机同一时间只有 1 个进行中的作业。扫 B 餐厅时提示“A 餐厅的作业尚未结束，是否先结束？”作业逻辑、App 提示（重要）
Q02同一家餐厅能否同时有多个司机（多辆车）在作业？允许，每个司机各自一条作业记录。作业逻辑
Q03手机位置与餐厅登记位置相距多远算异常？异常时是否阻止作业？只提示并记录距离，超过 200 米标记“位置异常”，不阻止提交。校验规则、监管依据
Q04司机拒绝定位权限或取不到位置时怎么办？（正式版）提示开启定位；仍取不到时允许继续，记录为“无位置”。原型中用模拟位置演示。App 流程
Q05作业开始后司机忘记结束怎么办？我们建议：开始满 8 小时仍未结束的作业由系统自动结束，标记为“系统自动结束”并记录在案，这样是否可行？开始后满 8 小时自动结束；记录自动结束时间与原因，抽取容量留空，由司机或管理署补填；管理署可在列表中筛选这类作业。作业逻辑、监管记录
Q06结束作业时是否必须拍照？要拍哪些（抽取前 / 后）？原型中拍照为可选，不强制。App 表单
Q07作业提交后能否修改或作废？由谁修改？司机不能修改；管理署可以修改或作废，所有修改留痕。权限、审计
司机与车辆
Q08一个司机是否可以登记多辆车？如果可以，作业时怎么确定用的是哪辆车？允许一个司机关联多辆车（车牌、罐体容积）；开始作业时选择本次使用的车辆，默认上次用过的车。数据结构（重要）
Q09抽取的废油量是否要与车辆的罐体容积对应？例如：单次抽取量不能超过车辆剩余容量；同一辆车连续去几家餐厅时，累计抽取量不能超过罐体容积。原型只记录车辆和抽取量，不做累计校验；单次抽取量超过车辆罐体容积时提示确认并标记“容量异常”。按车辆累计载量（含卸油后清零）在正式版与卸货功能一起实现。数据字段、校验规则
数据字段
Q10一家餐厅是否可能有多个化油池？原型按一家一个化油池。如有多个，正式版改为餐厅与化油池一对多，这会影响数据结构，需尽早确认。数据结构（重要）
账号与权限
Q11登录方式：账号密码，还是手机号加短信验证码？原型用账号密码；正式版再接短信验证码。登录、短信费用
Q12App 管理署角色的权限：流程里只写了查看和更新餐厅，是否还需要新增餐厅、管理司机？按流程：App 管理端支持查看、更新餐厅和审核司机；新增餐厅在 Web 端完成。原型范围
Q13管理署是否有多个账号或分级（如主管、巡查员）？原型只设一个管理员角色。权限设计
地区与部署
Q14系统在哪个地区使用？这决定服务器部署地点、数据存放要求和地图服务。评估目前按澳洲 AWS 悉尼区域估算；“化油池”“管理署”更接近港澳用语，需确认。部署、合规、费用（重要）
Q15地图服务用哪家：Google 地图、高德还是 OpenStreetMap？按使用地区决定；原型先用 OpenStreetMap。地图、费用
报表导出与 BI
Q16现在管理署从 Web 导出、再整合进自有 BI 系统的，具体是哪些数据？例如餐厅清单、抽取作业明细、逾期餐厅、警告罚款记录。包含哪些字段、什么格式（Excel / CSV）？能否提供一份现有导出文件作样例？新系统提供与现有导出字段一致的 Excel / CSV 导出；收到样例后逐个字段对应，保证 BI 那边不用改。报表、数据结构（重要）
Q17多久导出一次？是人工导出，还是需要定时自动导出？导出后怎么进入 BI（手工上传、共享文件夹、数据库直连、API）？用的是什么 BI 系统（如 Power BI、Tableau）？Web 上按日期范围手工导出；如需定时，正式版提供每日 / 每周自动导出到邮箱或文件存储，或提供只读 API 供 BI 直接拉取。接口、工时
历史数据迁移
Q18需要迁移哪些历史数据？时间范围多长？例如餐厅、化油池、司机、车辆、历史抽取记录、警告罚款记录、照片。迁移餐厅、司机、车辆和近 3 年的抽取记录；照片不迁移，或只迁移近 1 年。迁移工时（重要）
Q19现有系统的数据能否导出？以什么格式（Excel / CSV / 数据库备份）？由谁负责导出：管理署自己，还是原系统供应商？由管理署向原系统供应商申请导出 Excel / CSV；我方负责清洗数据、对应字段、导入新系统并出核对报告。迁移可行性（重要）
Q20新旧系统怎么切换：一次性切换，还是并行一段时间？迁移后是否需要管理署抽查核对？迁移后新旧系统并行 2 周，管理署抽查核对数据无误后正式切换。上线计划

6. 原型验收标准

  1. 在电脑浏览器中打开演示网址，可以在 Web 管理署后台、iOS 界面、安卓界面之间切换。
  2. Web 上能新增、编辑、停用餐厅（字段完整），能管理司机，能查看作业记录。
  3. 手机界面·管理署：能查看餐厅列表、按状态筛选、查看详情、更新餐厅信息。
  4. 手机界面·司机：模拟扫码与定位后，没有进行中的作业时可以新建作业；有进行中的作业时提示是否结束，结束时填写抽取容量。
  5. 作业结束后，Web 与手机界面都能看到记录，餐厅的“下次应抽日期”和状态随之更新。
  6. 演示数据可一键重置，便于反复演示。
